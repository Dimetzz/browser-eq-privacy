Purpose and audio

Browser EQ independently adjusts audio from multiple tabs activated by the user, not all Windows system audio. Each tab requires initial user activation and has a separate MediaStream, Web Audio processing graph and settings in one offscreen document. Audio is processed locally in memory, not uploaded or recorded to audio files. Switching tabs or closing the control window does not stop the streams. There is no manual stop button in the interface; tab closure or stream termination releases that capture independently. After a full browser restart, saved settings remain but MediaStreams require renewed user activation.

Tab URLs and settings

Version 0.5.16 reads a tab URL when the user activates Browser EQ on that tab. The profile system does not enumerate other open tabs or read their URLs at startup. The complete selected URL, including query and fragment, is used transiently to compute HMAC-SHA-256 with a randomly generated key stored locally in this extension installation. No plaintext URL is written by the new profile system.

A profile identifier contains the keyed digest and an occurrence slot. This is pseudonymization, not anonymization or encryption: someone with the local key and a candidate URL can compute a matching identifier. Query parameters distinguish content such as different videos. Session bindings are invalidated on navigation/loading or closure; persistent settings remain. A later activation can match the current URL again. Changed URLs may not match prior settings. After restart, profiles for exactly identical URLs are assigned in reactivation order, using the lowest available saved slot. This cannot guarantee the identity of indistinguishable restored tabs. Capture requires user activation. A new capture is refused if the tab or required URL becomes unavailable during preparation.

When controls are changed or reset, persistent local storage saves the pseudonymous profile identifier and EQ gains, EQ enabled state, compensation, input MONO, Spatializer enabled state, WIDTH, delay and FOCUS boundaries. Profiles and the local matching key remain after a tab closes and have no automatic expiry. Resetting controls resets values; it does not erase profile identifiers. Clear the extension storage or uninstall the extension to remove profiles and the key. Losing the key prevents matching saved identifiers.

On upgrade, old stored URL-based profiles are converted locally to keyed identifiers while preserving settings. Old plaintext profile keys are removed after replacement writes succeed. Old session-only bindings without a saved profile are discarded, including bindings created for unrelated tabs by 0.5.12. Migration does not read currently open tabs. If storage fails, migration can retry; old data may remain until migration completes. This does not erase external backups or earlier browser copies.

Session storage contains activated-tab/profile bindings (profileBindings), profile reservations for running streams (capturedProfileBindings), the selected UI tab ID (activeAudioTab), control window ID, fullscreen restoration state and optional diagnostic flag. Reservations keep a live stream associated with its own settings after navigation; they are released when it stops and reconciled with the live engines after worker restart. Basic tab IDs and window state are used to select the UI target, including an active-tab query for a focused browser window; this does not persist other tab URLs. Session storage is temporary. Persistent settings and the HMAC key use storage.local, not storage.sync; the extension does not cloud-sync them.

Diagnostics and fullscreen

The extension writes local console diagnostics about fullscreen events, tab/window IDs, state transitions and errors. An optional diagnostic mode adds capture/window information and timestamps. It does not send these logs to the publisher. Browser developer tools determine console retention; sharing logs manually is the user's choice.

For captured HTML5 video, the extension may switch that tab's browser window into fullscreen and restore its previous state on exit. Window and tab identifiers are used locally for this behavior.

Spatial presets

Built-in spatial presets change only the three existing delay/FOCUS values. No preset identifier or new personal-data category is stored. CUSTOM is derived from those values. Per-tab icons reflect capture/error state and retain explanatory hover text; no text badges are used.

Transfers and other data

Version 0.5.16 contains no analytics, advertising, telemetry service, publisher account login or remote executable code. Its implementation does not transmit audio, URLs, profile identifiers or settings to the publisher or third parties, sell them, or use them for advertising or credit decisions. It does not read page DOM contents or request microphone capture. Audio and URL-derived identifiers may be personal data. Version 0.5.16 uses temporary activeTab access rather than the broad tabs permission.

This policy describes the extension, not the independent behavior of websites, the browser or the Chrome Web Store. Changes to this policy should be published with an updated effective date. Contact the publisher above for privacy questions.
